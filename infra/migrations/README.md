# Migrations

Alembic revision history. Configuration is in `alembic.ini` at the repository root;
the connection URL comes from `DATABASE_URL` through validated application settings,
never from a committed file.

## Rules

- Migrations are forward-reviewed and tested. An already-released migration is never
  edited; correct it with a new revision.
- Every mapped class is imported in `env.py`. A model Alembic cannot see produces a
  silently empty autogenerated revision.
- Review every autogenerated revision by hand. Autogeneration is a first draft: it
  misses server defaults it was not told to compare, cannot infer a data migration,
  and will happily generate a destructive drop.
- Write a real `downgrade`, or state in the docstring why the change cannot be
  reversed.

## Commands

Run from the repository root, with `DATABASE_URL` set.

```powershell
uv run alembic upgrade head
```

```powershell
uv run alembic revision --autogenerate -m "short description"
```

```powershell
uv run alembic downgrade -1
```

```powershell
uv run alembic current
```
